# Apple II FujiNet 障害・タスク管理記録

本ドキュメントは、a2picoFN（Pico 2 W / RP2350 Wi-Fi SmartPort ブリッジ）および FujiNet 連携における障害事象、解析結果、および今後の技術課題を記録・追跡するためのものです。

---

## 障害記録: Lobby からの Five Card Stud ロード失敗（Error $27）

- **発生日時**: 2026-10-12 16:26頃
- **ステータス**: 未解決・解析中（次回以降の課題）

### 1. 事象概要
* Lobby（`_lobby.po`）から Five Card Stud（`apple2/5card.po`）を選択後、ディスクイメージのロード途中で Apple II 画面に以下のエラーメッセージが表示され停止した。
  ```
  Loading FCS ... ... Error $27 - Press Any Key
  ```

### 2. 発生環境
* **ハードウェア**: Apple //e + a2picoFN（RP2350 / Pico 2 W、ボードターゲット: `a2pico2litew`）
* **ホスト構成**:
  * Lobby 接続先: `tnfs.fujinet.online`
  * ゲームイメージ接続先: `ec.tnfs.io`（Host #7）
* **プロトコル / トランスポート**: Wi-Fi TCP ブリッジ（透明 SLIP SmartPort / RFC 1055）

### 3. ログ解析と事実関係
* `16:26:16`: `SET DEVICE SLOT 0x00/07/00` により `ec.tnfs.io` 上の `apple2/5card.po` が D1: へアサイン。
* 直前の `_lobby.po` がアンマウントされ、`5card.po` が正常にマウント完了。
* `16:26:19`: `Read block 000000` から順調にブロック読み込みが進行。
* `16:26:48.826`: Block `0x3E` の読み込み完了。
* `16:26:59.007`: Block `0x3F` の読み込み要求が発生（**約10秒のレイテンシ／無応答インターバルが発生**）。
* `16:26:59.185`: Block `0x3F` の再読み込み要求（リトライ）が発生。
* 直後に Apple II 側 ProDOS MLI が I/O タイムアウトと判定し、**Error $27（IO_ERROR: I/O Error）** を表示して停止。

### 4. 推定原因と今後の課題
1. **海外 TNFS サーバー通信遅延に伴う ProDOS タイムアウト超過**:
   * 海外 TNFS サーバー（`ec.tnfs.io`、往復 RTT 180ms〜240ms）からの大量ブロック連続転送時において、ネットワークパケットの遅延またはパケット滞留が発生し、ProDOS 側の応答待ち制限時間を超過した可能性。
2. **フロー制御およびリトライ耐性の検証**:
   * a2pico 側の Core 1（バス監視）/ PIO / Core 0（TCP バッファリング）間におけるデータフロー制御、およびホスト側一時遅延時のブロック読み出しリトライ耐性の確認。
3. **ローカル環境での切り分け検証**:
   * ローカル TNFS サーバー（`MMINI23.LOCAL` 等）に同一イメージ（`5card.po`）を配置した環境で再現試験を実施し、「インターネット／サーバー遅延起因」か「ファームウェア側のブロック処理・バッファリング起因」かを明確に切り分けること。
